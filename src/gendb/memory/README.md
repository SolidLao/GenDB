# GenDB Memory System v3

The memory system enables GenDB to learn across runs. Knowledge is stored in a 6-layer Hierarchical Abstraction Graph (HAG). Lower layers (L0/L1) use structural retrieval for query-level matching. Upper layers (L2-L5) are delivered as Claude Agent SDK skills for semantic discovery.

## 6-Layer Architecture

```
Layer 5: Performance Principles          ← Skill  (.claude/skills/principles/)
Layer 4: Optimization Strategies         ← Skill  (.claude/skills/strategies/)
Layer 3: Operator Techniques             ← Skill  (.claude/skills/operators/)
Layer 2: Sub-Structure Patterns          ← Skill  (.claude/skills/patterns/)
         |
Layer 1: Query Templates                 ← HAG    (gendb-memory/graph/nodes/L1/)
         |
Layer 0: Query Instances                 ← HAG    (gendb-memory/graph/nodes/L0/)
```

**Retrieval split:**
- L0/L1: Structural similarity (SQL feature extraction, Jaccard scoring) → tier classification
- L2-L5: Semantic matching by Claude (skill descriptions determine when to load)

## Skill-Based Knowledge Delivery

Skills are auto-generated by the Memory Manager agent after each run. Each skill is a directory:

```
.claude/skills/<category>/<skill-name>/
├── SKILL.md              # Description, when to use, technique
├── code-patterns/        # Generalized C++ templates with placeholders
├── evidence.json         # Performance data from past queries
└── gotchas.md           # Anti-patterns from regressions
```

Claude SDK agents auto-discover skills via `settingSources: ['project']`. No manual `load_memory` calls needed.

## Pipeline Integration

- **Phase 0**: Classify queries against L1 templates (exact/structural/novel)
- **Phase 2**: Agents receive L0/L1 pre-injection + native skill access
- **Phase 3**: Memory Manager extracts non-obvious knowledge, creates/evolves skills

## Key Design Principles

1. **Learn what's non-obvious**: Focus on iteration breakthroughs, not first-iteration successes
2. **Skills are benchmark-agnostic**: General patterns with C++ placeholders
3. **Evidence-driven**: Every skill backed by concrete performance data
4. **Progressive disclosure**: SKILL.md references supporting files; Claude reads when needed
